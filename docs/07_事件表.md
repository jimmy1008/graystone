# 07 事件表

> **動態化聲明（docs/09 優先）**：「豐年/歉收/暴雪/商隊延誤」不再是骰子——它們由每日天氣系統湧現（docs/09.A），已從下方隨機表移除概念上的獨立性（表格保留供對照）。真正保留隨機性的只有：狼群源、疫病源、塌方、狩獵受傷、新礦脈、遷入者、生育/婚配/死亡判定（參數在 `data/params.yaml` events/population 節）。

## 事件記錄鐵律

1. **流水帳不落盤**——「漢克今天修了一把鋤具」只改狀態，不進事件表。
2. 只有**值得記住的事件**落盤，結構化格式：

```yaml
event:
  id: E-Y1-042          # 年份+流水號
  day: 187              # 世界日
  type: injury          # 類型（見下表）
  location: forest      # 地點
  actors: [npc_09_1]    # 涉及者
  effects:              # 對世界狀態的實際改動（引擎執行的部分）
    - {target: npc_09_1, health: -30}
  caused_by: [E-Y1-039] # 因果邊（可空）——狼群靠近導致受傷
  known_by: [npc_09_1, npc_09_2, npc_12_1]  # 知情者（在場者+被告知者）
  notable: true
```

3. **落盤門檻**：涉及死亡/受傷/重大財產變動（>50G）/關係劇變（±15 以上）/職業變動/世界資源事件（塌方、歉收）——其餘不記。
4. `known_by` 從第一天就要維護——它是 Phase 2「NPC 只能談論自己知道的事」的基礎。情報透過酒館與市集傳播：在場者隔日將事件告知同地點者（機率 60%，孤僻減半）。

## 事件與因果圖

- `caused_by` 邊讓事件形成因果鏈（狼群靠近 → 獵人受傷 → 肉價上漲 → 某戶買不起肉 → 心情惡化）
- 引擎不需要「理解」因果——規則觸發時把觸發源事件 ID 寫進 `caused_by` 即可
- 年終壓縮：每年結束時，把當年未連入任何因果鏈、且 90 天內無人再提及的低重要度事件標記 `archived`（可清理）——重要事件與因果鏈**永久保留**，這是 08 講的 Canon 的一部分
