# 06 NPC 決策規則

> **架構更新（用戶裁決 2026-08-09）：30 個 NPC 全部接 LLM，不分階級。** 每個 NPC 都有 Agent 腦；規則系統的角色從「替 NPC 決策」變成「快速通道＋LLM 不可用時的後備」。優先目標：**先運作起來，讓歷史逐漸出現**。
>
> 運作方式（省算力同時人人有腦）：
> - **快速通道**：例行公事（按班表上工、吃飯睡覺）不呼叫 LLM，規則直接執行——這不是「NPC 沒有腦」，是「這件事不需要思考」
> - **抉擇點**：任何非例行狀況（缺糧怎麼辦、盈餘賣不賣、心情低落、剛捲入事件、閒冬夜晚）→ 該 NPC 的 LLM Agent 定奪，輸出 ACTION 提案 → 引擎驗證 → 執行或退回
> - **呼叫預算**：每模擬日 LLM 呼叫上限（params llm 節），按急迫度排序；排不上的退快速通道——預算是排程問題，不是階級問題，任何 NPC 都可能在任何一天輪到
> - **LLM 離線**：整個世界退化為純規則模式照常運轉（引擎必須支援 `--llm off`）

## 決策優先序堆疊（清晨段，由上而下取第一個命中）

```
1. 生存    戶內糧 < 3 天量        → 今日行動 = 買糧（找商店/村庫/鄰戶）
           冬季戶內柴 < 3 天量    → 今日行動 = 伐木或買柴
2. 職責    按【季節班表】工作（含秋收徵調、塌方停工等狀態檢查）
3. 補給    工具耐久 < 20%        → 傍晚去鐵匠鋪修理
           戶內鹽/布不足         → 傍晚去雜貨店
4. 社交    傍晚 30% 基礎機率去酒館（性格修正，見下）
5. 休息    無事者在家（體力恢復 +5）
```

- 不能勞動者（健康<30、體力<25、老人）跳過第 2 層
- 同戶協調：買糧/買柴一戶一天只派一人（戶主優先）

## 季節班表（第 2 層「職責」的內容）

| 職業 | 春 | 夏 | 秋（收成窗口外/內） | 冬 |
|---|---|---|---|---|
| 農民 | 春播→整地 | 照料田地 | 整備 / **收割** | 伐木、修繕 |
| 獵人 | 出獵 | 出獵 | 出獵（×1.1）/ **徵調收割** | 出獵（×0.5）+醃肉 |
| 礦工 | 採礦 | 採礦 | 採礦 / **徵調收割** | 採礦（×0.8） |
| 鐵匠 | 鍛造/接單，無單種田 | 同左 | 同左 / **徵調收割** | 鍛造旺季（農具修理） |
| 酒館 | 營業+釀造 | 同左 | 收購穀物+釀造 | 營業旺季（村民貓冬） |
| 商人 | 營業，商隊日對接 | 同左 | 秋收後售布旺季 | 同左 |
| 守衛 | 巡邏（村內+道路） | 同左 | 巡邏+護衛糧倉 | 巡邏（狼群季加強） |
| 草藥師 | **採藥季** | 採藥+診療 | 診療 | 診療旺季 |
| 村長 | 行政+自家田 | 同左 | **主持秋收+徵稅** | 行政+調解 |

徵調規則：收成窗口 15 天內，非農職業中「當日無更高優先事項者」下田（產出 22/天）。守衛與草藥師不徵調。

## 性格標籤 → 行為係數

每人 2~3 個標籤（見 npcs.yaml）。純規則版只做機率/係數修正；Phase 2 這些標籤直接成為 LLM 的人格輸入。

| 標籤 | 規則效果 |
|---|---|
| 勤勞 | 體力 25~49 仍工作（效率 0.7）；懶散：體力 <60 時 20% 機率翹工 |
| 吝嗇 | 酒館消費減半、賒欠追討加倍（關係扣分 −2/30天）；慷慨：鄰戶缺糧時主動借（無需被求助） |
| 好酒 | 酒館機率 ×2；孤僻：×0.5，且社交關係增益減半 |
| 暴躁 | 糾紛事件中升級機率 +20%；溫和：糾紛降級機率 +20% |
| 貪心 | 售價傾向 +10%，囤積傾向（存貨 >需求 2 倍才賣）；守舊：不改行、不接受新價格（沿用上期價） |

## 戶際互助與糾紛（傍晚段）

- **借糧**：缺糧戶向關係最好的鄰戶開口；對方存糧 > 自家 14 天量且關係 ≥ +30 → 借出（記 debts，30 天內還 110%）
- **拒借**：關係 −5；借出：關係 +3
- **糾紛觸發**：賒欠逾期、交易糾紛（動態價變動 >50% 的交易 10% 機率起爭執）、事件波及 → 關係 −5~−20，落盤為事件

## 職業變動（純規則版保留最簡版本；人口/技能/性格的完整動態見 docs/09）

- 連續 60 天收入低於全村中位數 50% 的勞動力 → 檢查轉職條件（有空缺+體力健康正常）→ 轉為副業為主
- 死亡繼承：戶主死亡 → 戶內最年長勞動力接任戶主；專業者死亡 → 學徒/子女以 Lv−2 接手（可能造成村莊機能退化——這是故意的）

## LLM 決策接口（全員適用）

每次呼叫給 LLM 的是該 NPC 的**結構化狀態**（身分/金錢/庫存/技能/性格/關係/近期 KNOWN 事件/當前狀況），要求輸出固定 JSON ACTION 提案（賣/買/借/贈/社交/休息/加班……小動作集，逐步擴充）。引擎逐項驗證（有沒有錢、有沒有貨、對象存不存在、世界法則允不允許），不合法就退回——**驗證退回本身也落盤**（它是「LLM 想做但世界不允許」的記錄，是研究幻覺率的數據）。

高權重 NPC（村長的稅率/平準售糧、商人的定價囤積、鐵匠的接單、酒館的收購與情報、守衛的巡邏）不是「才有腦」，而是**抉擇點天然比較多**——同一套機制，呼叫頻率自然分層。
